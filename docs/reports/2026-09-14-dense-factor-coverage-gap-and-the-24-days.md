## 1. 为什么"超过 10%"就等于"被丢掉"

三步，每步都已单独测过（见 `2026-09-14-yearly-deltas-and-the-24-unevaluable-days.md`）：

1. `best_simple` 基线工件的行集**恰好等于**"9 个稠密因子全都非空"的行集
   （整折集合相等、对称差为 0）；候选则给每一行都打了分（逐日覆盖率恒为 1.0000）。
2. `evaluate_frozen_oos` 先取两者键的**交集**再算逐日 RankIC，
   所以当天的 coverage = 稠密因子完整的行 / 有效标签行 = **1 − 稠密不完整份额**。
3. `ScoreHealthEvidence.passes()` 要求 **`0.90 <= coverage <= 1.0`**，
   即 **稠密不完整份额 ≤ 10%**；超过就整天不可评。

所以"哪些天被丢掉"完全由**稠密不完整份额是否越过 10%** 决定，与模型无关。
实测逐年份额：

| 年 | 有效标签行 | 稠密不完整行 | 份额 | 涉及证券数（占全部） | 科创板受影响/在架 | 份额 >10% 的天数 | 逐日份额 min/中位/max |
|---|---|---|---|---|---|---|---|
| 2022 | 803,572 | 57,051 | **7.10%** | 688 / 4,342 | **326 / 326（100%）** | **1** | 0.0517 / 0.0746 / 0.1049 |
| 2023 | 881,863 | 61,554 | **6.98%** | 686 / 4,714 | **427 / 457（93%）** | **23** | 0.0045 / 0.0907 / 0.1097 |
| 2024 | 931,411 | 7,666 | 0.82% | 319 / 4,882 | 26 / 490 | 0 | 0.0034 / 0.0076 / 0.0289 |
| 2025 | 936,317 | 13,332 | 1.42% | 331 / 4,911 | 48 / 543 | 0 | 0.0105 / 0.0141 / 0.0191 |

**"份额 >10% 的天数"这一列（1 + 23 + 0 + 0 = 24）就是被丢掉的那 24 天**，
与逐日 RankIC 帧里 `rank_ic_valid=False` 的日子逐日相同。
2023 年最坏的几天：`07-05` 0.1097、`07-14` 0.1020、`07-10` 0.1017、`06-30` 0.1016、`07-12` 0.1015；
2022 年唯一那天是 `07-29`（0.1049）。**2023 年的中位数是 0.0907**，
也就是说**整年都贴着 10% 这条线**——这解释了为什么"42 天以不到 0.005 的余量通过"。

## 4.1 更正（2026-09-15 00:10）：成因已查明，**不在因子生产侧，在我们自己的重放输入**

只读排查（select-only，未改任何代码、门值、冻结集、签名工件或数据库）把整条链在同一天上对齐，
四段的结果互相矛盾，而矛盾点就是答案：

| 段（2023-07-05） | `yeslab_357` | `yeslab_471` | 对照 `yeslab_381`（同表 data8、同一次物化） |
|---|---|---|---|
| 上游 YesLab 存量 | 科创板 588 只、**540 只有值**、无 inf | 611 只、527 只有值 | 606 只、539 只有值 |
| `factor_daily`（2026-09-03 物化） | 3,274 行、**科创板 0 行** | 3,258 行、**科创板 0 行** | 3,625 行、**科创板 318 行全有值** |
| published pin vs manifest | **一致**（单一 data_version） | 一致 | 一致 |
| 已发布面板 | 报缺 354 行（318 科创板） | 报缺 370 行（318 科创板） | 报缺 3 行（0 科创板） |

逐代码对齐（不是总量对齐）：面板报缺的 354 个代码里，**353 个在上游当天有非空值，含全部 318 个科创板**；
2022-07-29 是 **283/283，含全部 181 个科创板**。所以**上游不缺**。

**根因（指名到代码行）**：`research_v2/scripts/materialize_frozen_factor_daily.py` 的冻结链
**不抄 YesLab 存量值，而是从 Tushare 行情重放公式**，并且只给三个因子传 PIT 行业提供方：

```python
PIT_FACTORS = {"yeslab_357", "yeslab_363", "yeslab_471"}   # 冻结集里只有 357 与 471，363 不在集内
PIT_CUTOVER = date(2021, 12, 10)                            # 之后走 SW2021 那一支
provider = VersionedPITIndustryProvider.from_cache(CACHE, cutover=PIT_CUTOVER)
prov = provider if fid in PIT_FACTORS else None
```

而它读的 SW2021 成分缓存（`research_v2/artifacts/tushare_cache/pit_industry_members_*_SI.json`，
31 个文件、7,733 行）里：**科创板 688/689 共 624 行 / 612 只，最早的 `in_date` 是 2023-09-25**
（其中 **559 只在同一天入册**），而非科创板 7,109 行 / 4,885 只、最早可追到 **1990-12-10**。
按日重算在册成员：2022-07-29 / 2023-07-05 / 2023-09-01 的科创板在册数都是 **0**，2023-09-25 起为 **558/559**。
行业标签拿不到 → 重放算不出值 → `factor_daily` 没有这些行。
这同时解释了本文 §2 测到的两件怪事：**两个不同表、不同所有者的因子逐月缺口行数完全相同**
（2023-07/08/09/10 = 0 / 0 / 1,286 / 5,522），而**同表对照因子全程满覆盖**
（6,596 / 6,458 / 6,230 / 5,539）——对照因子不取行业标签，这个洞够不到它。

**两处算术闭合**：

1. 2023-09-25 是周一，9 月 25–28 共 **4 个交易日**（09-29 中秋、10-01～06 国庆）。
   **1,286 ÷ 4 = 321.5 行/日**，10 月 **5,522 ÷ 17 = 324.8 行/日**（该月交易日数实测 17）——同一口径。
   缺口不是逐渐恢复的，是在 2023-09-25 **整体开始**的，与缓存里 559 条同日 `in_date` 对应。
2. `factor_rank_ic_daily` 是 **2026-08-02**（早于 9-03 那次物化）算的，其 `sample_count`
   是对当日截面宽度的一次带时间戳的测量：2023-07-05 `yeslab_357` = **3,626**
   （对照 `381` = 3,622、参照 `yeslab_0` = 3,622、当日有效标签行 = 3,627），
   2022-07-29 = **3,355**（= 当日有效标签行数）。**8 月时它的截面是完整的**，
   缺口与 9-03 那次重放同时出现——这排除了"上游是后来才回补的"。

**另外三条也被逐一排除（都是实测，不是推断）**：

* **生产端缺口**：见上，上游对完全相同的键有有限值。
* **版本钉住过期**（`filter_current` 只留 pin 指向的版本）：区间内**只有一个 data_version**，
  且 `published_version` 钉住的 == manifest 消费的。
* **隔离/修复路径丢行**：`factor_repair_audit` 与 `factor_repair_quarantine` **全表 0 行**；
  `factor_quarantine` 有 536,627 行但**只覆盖 2025-01-02 至 2025-01-27**（reason 全是 `NO_FINITE_VALUE`、23 个因子），
  对 2022/2023 没有任何记录。**排查中我一度把这份沉默当成"物化从未见过这些键"的证据，这一步无效，已撤回。**

**顺带解释了 §3 里那个说不通的现象**：`689009.SH` 四年里每个交易日都缺、10 月的好转没覆盖到它——
因为该代码**在行业缓存里完全不存在**（0 行）。面板点名的 `688567.SH`(188 天)、
`688002.SH`/`688003.SH`/`688005.SH`(各 178 天) 四只都在缓存中、`in_date` 均为 2023-09-25。

**可复现性警告**：数据商重述过这段行业历史——今天查 `688002.SH`，带 `src=SW2021` 过滤返回空，
不带过滤返回 `in_date=2026-08-21`、一级行业 `801080.SI`（电子），与缓存里的 `801740.SI` / `2023-09-25` 不一致。
所以**只有当时那份缓存才是重放真正看到的输入**，重新取数不能复现本结论；
32 份缓存原件已随证据包逐字节复制（见下"证据与重跑"）。

**证据与重跑**：7 个只读探针 + 11 份机读测量与终端记录 + 32 份行业缓存原件 + 全部 sha256，
在分支 `codex/research-conditional-factor-review` 的
`docs/research/evidence/2026-09-14-model-side-walk-forward/star_industry_coverage/`
（叙述文档 `root_cause.md`，含论文措辞与三个处置选项）。

## 5. 对论文与对平台的含义

**对论文（方法学限制该怎么写）**：
"OOS 日集为 945 天（G6 = 945/969）。被排除的 24 天不是因为候选模型无法打分
（候选逐日覆盖率为 1.0000），而是因为冻结基线只在 9 个稠密因子齐备的行上有定义，
而 2022–2023 年 `yeslab_357` 与 `yeslab_471` 对科创板股票成对缺失，
使 24 个交易日的稠密不完整份额越过 10% 的分数健康下限。
该排除对候选与基线同时生效，且关掉下限后两个候选的增量都变大
（M0R +0.009149 → +0.009542、M1 全网格 +0.007827 → +0.008194），
因此它对候选是保守的。**（以下两句按 §4.1 补入）** 这两个因子在我们的可复现重放口径下依赖点时行业分类，
而所用的申万 2021 版成分记录中科创板成员最早自 2023-09-25 起才有登记；权威因子存量库对同样的
（证券, 日期）键确有有限值，但按预注册的数据口径，冻结链的因子值一律来自重放产物 `factor_daily`、
不混入历史存量值，故本文不使用这些值。"

**移交（按 §4.1 改向）**：~~对因子侧的移交问题~~ **不再移交因子所有者**（suyanning / zhangyudong）——
成因不在因子生产端，上游存量对这些键有值。接手方是**平台/重放口径的所有者**，
要决定的只有一件事：**要不要为 `yeslab_357` / `yeslab_471` 补上 2023-09-25 之前的科创板行业历史**。
三条路，本轮**一条都没做**（冻结集与已签名报告原样）：

1. **维持现状 + 论文披露**（上面那段措辞）。已测得该排除对候选**偏保守**，所有已发布数字不变。**本轮采用。**
2. **补行业输入的历史科创板覆盖后重放这两个因子**：`factor_daily` 会变 →
   冻结链所有已签名报告与门值都变 → 等于开新谱系（要重跑候选链、重签证据）。
3. **治理例外**：允许这两个因子在 2023-09-25 之前使用 YesLab 权威存量值。
   违反"不混历史 YesLab 值"的预注册约束，同样需要新谱系，并且必须作为一次显式的口径变更记录。

**对平台的一个观察（不改，只记）**：G6 现在度量的是**基线工件的稠密因子完整性**，
而不是候选的打分能力；而 2023 年整年都贴着 10% 这条线（中位 9.07%），
所以"哪些天进样本"对这条线高度敏感。
若将来重新发布覆盖率完整的冻结基线，这 24 天会全部回到样本里、G6 变成 1.0，
但**每个门值都会变**，等于开新谱系——属所有者裁决，本文未做。

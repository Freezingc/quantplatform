## 1. 交接前提

模型训练只能在**因子集冻结后**开始。流程：

1. 你在决策清单填好「决定」列 →
2. 运行 `scripts/apply_admission_decisions.py`（先 dry-run 看冲突，无冲突后加 `--apply`）→
3. 脚本写 `factor_set_frozen`（DB）+ 更新清单 + 产出 `factor_set_frozen_v1.json` →
4. 本文档生效，进入训练。

## 2. 冻结因子集的来源与口径

- **因子值来源**：`dfs://QuantResearchV2Test.factor_daily`（准入流水线物化的因子值，隔离规范版本，勿混历史 YesLab 值）。
- **标签**：`label_daily` 的 `forward_open_5d:v1`（5 交易日前向复权收益）。
- **宇宙**：训练/评估一律用官方 `universe_daily` 的 `cn_liquid_a`（直读，勿静态复现——有 ~17% 漂移，见简报 4w）。
- **质量证据**：三张新表 `factor_window_quality`（分期 IC/ICIR）、`factor_pair_redundancy`（冗余）、`factor_quality_grade`（分级）。

## 3. 监控要求（准入后必须保留）

各因子监控见决策清单 A 表「监控要求」列。跨因子体制监控统一用 4x/4y 两个已验证指标：

- **大盘股主导体制**：沪深300−中证500 60日收益差 ≥ 0.10（`largecap_dominance_regime_v1/`）。
- **急性流动性冲击**：中证1000 20日收益 ≤ −0.08（`liquidity_shock_regime_v1/`）。
- **监控并集触发**：任一指标 ON → 对相关因子（尤其 437/431/443 及 443 修复变体）启动降权评估。

## 4. 体制感知加权（对崩塌因子）

437/431（正式因子，2017 崩塌）与 443/443修复变体在大盘股主导体制下失效。模型阶段处理（对应决策点 D3 选 a）：

- 当「大盘股主导」指标 ON 时，对 437/431/443(修复变体) 的预测贡献降权（建议降至 0 或 0.3，具体由训练调参定）。
- 该加权规则应在 walk-forward 的 OOS 段验证有效性后再固化。

## 5. 训练基建（并行会话在建）

- Walk-forward 复现基建：`scripts/run_real_walk_forward.py`（criterion-303，folds F01-F06），并行会话推进中。
- 冻结因子集落地后，把冻结集合作为训练的因子输入清单，替换当前占位。

## 6. 训练阶段的检查点

1. 冻结集合规性：确认 `factor_set_frozen` 与 `factor_daily` 的因子对齐（无缺失、无混入历史值）。
2. 训练/验证分割：沿用 2020-2024 训练、2025 验证的口径；锁定测试段（2026）严禁用于调参。
3. 体制加权的 OOS 验证：在验证段确认加权不损害整体、且降低崩塌体制下的回撤。
4. 训练完成后把模型 OOS 指标回写诊断产物，并与分级预期（S/A 级因子应贡献主要增量）对照。

- 不在锁定测试段（2026）上做任何训练/调参。
- 不复用历史 YesLab 因子值（只用隔离规范版本）。
- 437/431 若决策选 (b) 修复探索，须另行授权后再启动。

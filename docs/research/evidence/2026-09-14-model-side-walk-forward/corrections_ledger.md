## D. 引用规则（给写论文的人）

1. **四载体网格统计（§BO.1 那张表）**：**M0-base / M0-refined / M1 三行可以照引**（四折、单一模型状态、未受影响）；**M2 那一行不要照引**——它是 `b=1`，改用 §CB.1 的 `b=2` 值，并在 F3/F4 落盘后再更新一次。
2. **任何"配置效应 / 轴效应"的结论**：**必须声明是末轮口径还是峰值口径**。树载体（LightGBM）只有一个模型状态，不存在这个二义性；**M1 与 M2 存在**，两者结论可能相反（见 A5、A6）。**描述发运模型的是峰值口径。**
3. **`lr=3e-4` 这条建议**：**不建议写进论文**（A6 + A7）。**可以写的是 `family=TCN` 与 `hidden_dim=64`**，它们在两个口径上都显著（峰值口径 `p=1.21e-03` / `2.94e-03`，Bonferroni 阈值 0.00625 下入档）。
4. **多重比较**：**§BO.9 自定的标准是"只把 `p<1e-4` 与四折全稳定当作可靠"**。按这把尺子，峰值口径下 M2 四条轴没有一条入档（最好的 `family` 是 `p=1.21e-03`）；按 8 个轴检验的 Bonferroni（0.00625）则 `family` 与 `hidden_dim` 入档。**引用任何轴级 `p` 值时请一并给出用的是哪把尺子。**
5. **"首次出现"≠"IPO"**：**准入不是新股专属通道**，任何证券都可以在任意年份重新进入面板（四折共 8 个 lag ≥ 6 年的再进入，其中 4 个已退市；最极端的是上市于 1990-12-19 的 `600654.SH` 中安科在 2024 年首次出现）。**这两个概念必须分开陈述**（§BZ.5）。
6. **走前设计的一条固有限制（值得写进 limitation）**：**因为同年准入恒为 0，F4（测试年 2025）完全不含 2025 年上市的任何证券**，所以这个设计在**任何一折**上都无法检验"模型对当年新股的泛化能力"。**这是准入规则的四折共性，不是 F4 独有的缺陷**（§BX.8 第 4 条）。
7. **跨折重复计数**：**任何把"每折首次出现"跨折相加的统计都要先去重**（24 家证券被两折各计一次；非相邻折对重叠为 0）。**§BZ.4 的去重矩阵是正确版本，机读件里那份朴素的键名带 `_DO_NOT_USE`。**
8. **凡是涉及"哪个配置最好"的结论，必须先问它是哪个载体的**：**M2 的 F1/F2 可以放心引用**（峰值、末轮、驱动三者选同一个配置）；**M1 的四折胜出配置不得引用**——它与"发运模型的质量排序"几乎不相关（spearman −0.14 到 +0.23），**要引用 M1 的网格结论请只用 §CB.3 / §CA.4 那两节的轴级与方差结论，不要用它的"每折冠军"**（§BO.7 那条"每折冠军都是任意的"在 M1 上因此格外成立）。
9. **OOS / G6 / G4 这一类数字可以照常引用**：§CC.1 已用哈希实测确认发运权重就是峰值检查点（15/15 逐字节相同），§CC.2 确认 test 预测由 bundle 重建的模型现算，**所以 §CA 那个缺陷不影响任何已发布的 OOS 侧数字，只影响"选了哪个配置"**。
10. **那 242 行「九个稠密因子全缺」可以直接按 §CE.3 的三项分解引用**（238 + 3 + 1，可打分 241），**并且要带上口径说明**：238 是「陈旧 `max()` 选中错误宇宙版本」、3 是「退市前 3–4 周的证券」、1 是「九列全缺但无有效标签所以不可打分」。**不要把 238 与 §BS 的 17,306 行相加**——前者是稠密因子全缺、后者是历史长度不足，两个定义不同且重叠未测（§CE.5 第 3 条）。
11. **合并 §CG 那个修复之前后，验证侧数字不可直接比较**：合并前 `seed_validation_rank_ic` / `ensemble_validation_rank_ic` 描述**末轮**模型（已发布的 §BO / §BN / §BY / §CA / §CB / §CD 全部是这个口径），合并后同样这两个字段描述**峰值轮**（即发运的）模型。**已经跑完的 M1 四折与 M2 的 F1/F2 是旧口径；M2 的 F3/F4 若在合并之后跑就是新口径，会造成同一次运行内部口径不一致**——所以合并时机要么等 M2 四折全部跑完，要么接受不一致并在报告里写明。**OOS 侧不受影响**（OOS 由 `load_bundle_for_evaluation` 从持久化的 `seed-*.pt` 重建模型再重算 test 预测，而 §CC.1 已用 15/15 哈希实测确认那就是峰值检查点），**已发布的 OOS RankIC / G4 / G6 合并前后都描述发运模型**。
12. **合并 §CG 那个修复的时机有讲究，而且理由是科学有效性、不是崩溃风险**：**不要在 M2 跑完之前合并**——驱动的 cwd 就是主工作树，而 `run_parallel_search` 每次调用都用 `spawn` 新建进程池（`parallel_search.py:233-236`），所以新 spawn 的 worker 会从磁盘重新 import：**F1/F2 的检索记录是旧口径、F3/F4 会是新口径，一次运行的四折不可比，这会破坏所有跨折合并的统计量**（§BO.1 四载体表、§BN 方差分解、§CB.1/§CB.2 抵消比，前提全是"四折同口径"）。**若合并落在某折的网格搜索与胜出配置重拟合之间，还会在同一折内部混口径**（M2 此刻正处在 F2 重拟合阶段）。**反之，合并本身零冲突**（deferred 改 8 个文件、主分支改 12 个、交集为 0），**且修复依赖的 `CheckpointStore.load()` 在主树已存在、`artifacts.py` 两侧逐字节相同（sha256 `5b3bfdf6…`），所以合并后 worker 不会 `AttributeError` 崩溃**。**结论：等 M2 四折跑完再合并，然后跑一遍 `pytest tests/unit tests/integration tests/golden`（deferred 分支上 2092 passed / 46 skipped / 0 failed）即可，不需要额外准备。** **「等着」的代价已由 §CI 量化**：M2 剩余墙钟按四个情景是 **166.6 / 252.0 / 337.9 / 523.8 小时（6.9 / 10.5 / 14.1 / 21.8 天）**，对应完成时间 **2026-09-25 到 2026-10-10**，整轮总长 11.9–26.8 天；成本模型 `k × epoch/运行 × 面板行数` 在 F1/F2 上验证到 **2.4%** 误差（`k` 两折只差 2.5%），**区间之所以宽，是因为 epoch/运行只有两个观测点（17.49 与 28.81，涨 1.647 倍），两点无法区分线性、几何与「F2 恰好偏大」**。**所以 §CH 那条「等 M2 跑完再合并」的建议，按中位情景意味着合并要等到约 2026-10-02；这是所有者需要在「口径可比」与「多等约两周」之间权衡的真实代价。** **另有一条不必等四折的事**：§BQ.4 投影表里 **F2 那一格可以在 F2 的重拟合结束、`models/m2-f2` 写出之后立刻换成实测**（OOS 评估只需该折的 test 侧预测），这是 M2 跑完前唯一还能推进的实测项。

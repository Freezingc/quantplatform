## D. 引用规则（给写论文的人）

1. **四载体网格统计（§BO.1 那张表）**：**M0-base / M0-refined / M1 三行可以照引**（四折、单一模型状态、未受影响）；**M2 那一行不要照引**——它是 `b=1`，改用 §CB.1 的 `b=2` 值，并在 F3/F4 落盘后再更新一次。
2. **任何"配置效应 / 轴效应"的结论**：**必须声明是末轮口径还是峰值口径**。树载体（LightGBM）只有一个模型状态，不存在这个二义性；**M1 与 M2 存在**，两者结论可能相反（见 A5、A6）。**描述发运模型的是峰值口径。**
3. **`lr=3e-4` 这条建议**：**不建议写进论文**（A6 + A7）。**可以写的是 `family=TCN` 与 `hidden_dim=64`**，它们在两个口径上都显著（峰值口径 `p=1.21e-03` / `2.94e-03`，Bonferroni 阈值 0.00625 下入档）。
4. **多重比较**：**§BO.9 自定的标准是"只把 `p<1e-4` 与四折全稳定当作可靠"** **【2026-09-19 12:45 限定（§CV）：「四折全稳定」不是四次独立确认——四折是步长 1 年的滚动 4 年窗口（`splits.py:58-65`），相邻折共享 3/4 训练年、16 个 fold-year 只覆盖 7 个不同年份（复用因子 2.286）、2020 年在全部四折的训练集里，所以一个由某个特殊年份驱动的结果可以同时出现在三折甚至四折里；有效折数在 1 与 4 之间。引用这条判据时必须带上这个限定，并在论文 limitation 里写明。经验检验在配置基础上跑四个（M1 集成 −0.3230、M1 种子均值 −0.0631、M0 集成 −0.0995、M1 峰值 epoch +0.1905），3/4 为负、0 个显著为正，即没有出现重叠所预测的正邻接依赖（§CW/B27 已更正 §CV.5 那个「符号翻转、不可判定」的判定，它源于把 27 行与 81 行两种分析单位并列）；但这不等于「四折独立」，因为纯折主效应对该检验不可见、且数据复用本身与相关系数无关，所以不得把「测不到邻接信号」写成「四折等于四次独立确认」。另有一个校准陷阱：对四个折值逐行去均值本身就制造 E[corr] = −1/(k−1) = −0.3333，任何折间相关矩阵都不能对着 0 读。详见 §CV 与 B26】**按这把尺子，峰值口径下 M2 四条轴没有一条入档（最好的 `family` 是 `p=1.21e-03`）；按 8 个轴检验的 Bonferroni（0.00625）则 `family` 与 `hidden_dim` 入档。**引用任何轴级 `p` 值时请一并给出用的是哪把尺子。**

15. **epoch/运行 的折间模式（§CK.2 四折值 + §CN 的种子依赖）**：**「M1 四折 epoch/运行 = 20.12 → 23.27 → 19.09 → 16.96、F2 见顶后回落」可以引用，但必须声明这是对 3 个种子取平均的合并值**（§CN.4/B19）。**逐种子看，这个「先升后降」形状只在 3 个种子里 2 个成立**（seed 20260801 的 argmax 是 F4），**因为折×种子交互的效应量（14.52% SST）比折主效应（7.17% SST）还大，且高度显著**（p 值随模型不同：§CN 的模型 B 是 1.68e-12、§CP 多加 config×seed 项后是 9.02e-12，因为残差 df 从 208 变 156；所以引用时请用与残差无关的 SS% 比较，即 14.52% > 7.17%，不要脱离模型引用单个 p 值）。**更要紧**：**在峰值 epoch 这个因变量上，种子主效应（16.28% SST、摆动 8.35 epoch）大于折主效应（7.17% SST、全距 6.31 epoch），而在验证 RankIC 上两者相反（种子 0.88% 对折 74.53%）——即「峰值在哪一轮」由种子主导、「峰值有多高」由折主导**。**任何「折 X 上约 N 轮收敛」的陈述都带着与折效应同量级的种子不确定性，引用 §CI 的 `epochs_per_run`、§CK.2 的四折表、§CJ 的峰值扫描时都要说明是「3 个种子的均值」**。**F3 与 F4 的比较必须声明口径**：**按均值 F3（9.086）> F4（6.963），但按中位数 F3（3）< F4（4）、按 25% 截尾 F3（4.756）< F4（5.488）——两者给相反答案，因为 F3 双峰、F4 不双峰**（B17②/B20）。
16. **可观测性上限（写进 limitation）**：**早停只在严格改善时保存检查点（`trainer.py:110-116`），所以峰值之后执行的 epoch 一行痕迹都不留**。**实测可观测比例**（保存检查点数 ÷ 执行 epoch 数）**：M1 只有 24.4%、M2 43.8%**；**23 个 M1 与 16 个 M2 网格运行只有 1 个检查点**（对它们全部证据就是「epoch 1 是峰值」，而实际约跑 11 轮）。**因此「峰值之后的曲线形状」在本框架里不是「没测」而是「数据不存在」**——**§BO.9 / §CA / §CB / §CI / §CJ / §CK 所有训练动态统计算的都是峰值，这对「在哪里收敛」正确且充分，但对「收敛后掉多快」一个字都没有**。**论文应当把这条写进 limitation**：**本框架的训练曲线是「改善点的稀疏采样」，不是逐轮曲线**（§CM.3）。

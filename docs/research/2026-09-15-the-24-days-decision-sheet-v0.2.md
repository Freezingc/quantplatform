## 5. 本文没有做的事

* 没有改任何代码、缓存、门值、地板、冻结集、签名工件或数据库；
  `research_v2/artifacts/tushare_cache/` 一个字节未动，数据库只做 SELECT。

## 6. 同日追加的三条实测（05:15），都影响选项 1 的执行方式

完整叙述与逐日表见 `evidence/…/star_industry_coverage/option1_feasibility.md` §8–§12，
机读件 `measurements/option1_{gap_row_classification,union_vs_replace,other_failure_shapes,bulk_expiry_days}.json`。

1. **缺口行按证券四分类**（先逐日复现仪器，分子分母 24/24 全同）：
   24 天共 **8,782** 缺口行 = 可修科创板 **7,544** + 可修非科创板 **136** +
   **已有标签、缺的是其余七因子之一的 1,101（补标签救不了）** + 两支 API 都无标签的 **1**。
   可修的 7,680 行里 **7,639 行（99.47%）正好缺那两个行业因子**。
   → 顺带发现一个此前没记录的缺口：**缓存每天还少 460–614 个非科创板证券的标签**，贯穿整个窗口。
2. **选项 1 必须做成并集，不能做成替换。**
   两支 API 把年度成分调整的空洞放在**不同的日子**（缓存 2022-07-29 到期 143 条；
   `index_member_all` 2022-07-28 到期 243 条，两者失标证券**只重合 5 个，重合率 0.020**）。
   并集失标恒为 0、跌破 0 天、最差日 0.976751；替换跌破也是 0 天、G6 也是 1.000000，
   **但把 2022-07-28 压到 0.903697、只剩 12.4 行余量**——与本文已否掉的"只移 `yeslab_206`"（0–8 行）同一类。
   **并集需要一条显式优先级规则**（建议：同日两支都有标签时以 `index_member_all` 为准，只在它缺时用缓存兜底），
   因为两支在 39 天上有 114 对标签取值不同；**这条规则本文没有实现也没有验证**。
3. **另外两处失效形状一并消失，所以选项 1 同时是训练年的修复。**
   ① 2014 左端：缓存 2014-01-02 只有 **20/31** 个行业、2014-02-21 一次性入册 **912** 只；
   `index_member_all` 自 2014-01-02 即 **31/31**、当天入册 **1** 只。
   ② 2021-12-10 cutover 空洞：缓存当天 **535** 条到期、在册 4,338 → **3,806**；
   `index_member_all` 当天到期 **1** 条、在册 4,803 → **4,812**，**无空洞**。
   但**不要**由此推断训练年那 1,045/1,948 个跌破日都会被救：§9–§13 已归因出 2014–2017 的薄弱
   主要来自 `yeslab_206` 与 `yeslab_443_reg30_max20_v1` 两个修复变体，与行业标签无关。

**§5 追加两条"没有做"**：没有实现也没有验证并集的优先级规则；没有量化"并集会掩盖真实到期"这一固有代价
（某证券真的退出某行业时，缓存那一支仍会给它标签）。
